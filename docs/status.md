## Local verification

- TypeScript checks and Next.js production build are run during implementation.
- Unit tests cover permissions, no-upscale profiles, configurable profile ladders, chunk boundaries, integrity/HMAC verification, replay window, Arabic subtitle conversion, production sprite delegation, signed sprite playback URLs, WebVTT `#xywh` crop rendering, packaging-time preview asset requirements, alternate-audio HLS master contracts, player audio-track switching, CMAF/fMP4 packaging contracts, signed CMAF/audio URI delivery, CMAF readiness gating, persisted CMAF media MIME types, paginated object-store output reconciliation, deep stored-media playlist reference verification, and post-readiness media-health quarantine contracts.
- Real FFmpeg tests generate a short 720p clip, produce renditions, decode each playlist, generate poster/sprite preview assets, process a silent small source, and validate a two-track English/Arabic source through both MPEG-TS HLS and CMAF/fMP4 packaging. The sprite scaler is exercised against real FFmpeg to prevent aspect-ratio rounding from overflowing fixed preview cells.
- The Docker stack test covers real services and the core API/media workflow. Consult the repository's current CI status; local build success alone does not prove Docker startup.
- Direct browser multipart upload requires object-storage CORS to allow the web origin, PUT, and expose the `ETag` response header.
- Flutter source is not claimed to have passed `flutter analyze` or device tests in an environment without Flutter.
- A full browser automation/accessibility suite and a public HTTPS webhook receiver test remain outstanding.

The initial release should be treated as a reviewable implementation of the core workflow, not a certification of production readiness or completion of all six phases.
